# Step 2 — Rehearse dispatch and review offline

Use the frozen inputs from [Step 1](phase-1.md). The integration owner defines the run and receipt identities first. Then two local units are [batch-eligible]: the runner and its tests at `Scripts/explain-qualification-run:239` and `Scripts/tests/test_explain_run.py:102`, and the review/scorer plus their tests at `Scripts/explain-qualification-review:77`, `Scripts/explain-qualify:83`, `Scripts/tests/test_explain_review.py:41` and `Scripts/tests/test_explain_qualification.py:88`. The owner integrates them and alone updates the verification policy.

**Run identity.** Bind the experiment, authorized arm/occurrence, ordered cohort, candidate configuration, model, fixture manifest, request set, per-case wire digest and prospective review rules. Allow only one new occurrence of the unchanged control. Give the six-case treatment, optional example and conditional full run distinct identities. Keep prior run directories read-only. Extend the existing prepare, selector and dispatch paths. A second arbitrary occurrence or a free-form run label must never bypass replay prevention. A six-case receipt cannot satisfy full qualification.

**Reservation and interruption.** Before sending, preview exact frozen bytes through the supported provider price bound at `Scripts/explain-qualification-run:55`. Verify current pricing covers the model, tier and output budget. Take an exclusive aggregate reservation for the run’s entire worst-case dollars and request count, checking prior and in-flight reservations atomically. Record and flush the authorization, then record each attempt durably before network IO. Keep whole interrupted reservations charged against the envelope. Concurrent commands, crashes and retries must preserve the upper bound. Expose a read-only status listing candidate, arm, reserved counts/dollars, completed cases and any incomplete attempt. Store raw answers, review keys and text-bearing notes in ignored evidence. Stage sanitized receipts and publish without overwriting prior runs.

**Blinding and scoring.** Randomize opaque answer labels. Strip run, model, arm, case ID and order clues from reviewer packets. Give two independent readers the source, fact sheet and frozen factual rubric. Collect a factual verdict, ambiguity, all fact-index dispositions and near-verbatim flag. Collect a separate perceived style (Plain, Examples, Metaphors, Picture or indeterminate) without revealing the requested style before that choice is locked. Then join the expected setting. Readers must recognize the intended style even for factually passing answers. Retain both original judgments. Resolve disputes by a third blinded adjudication with a quoted source and explanation. An unresolved judgment fails its criterion. Record rubric/version, evidence bindings, the final perceived style and adjudication outcome in the new schema. Keep free-text quotations in private review evidence. For 83 cases the same two judgments and decision rule apply.

```text
@ score(run, verdicts) -> diagnostic rows or full disposition
pre: complete attempts and natural-stop observations bound to frozen request bytes
do:
  1. validate each label and answer digest within its run and cohort
  2. compute source and answer words from the actual strings
  3. lookup required facts and compare perceived style to requested style
  4. emit each failed criterion and each cohort total
br: unresolved disagreement -> record a miss and retain both reviews
fail: duplicate, missing, swapped or unbound evidence -> withhold disposition
```

**Historical records.** The current reader enforces exact fields and version 1 at `Scripts/explain-qualify:83`, and the writer expects the current canonical configuration at `Scripts/explain-qualification-review:125`. Route historical evidence through its own schema and recorded identity. Display unmeasured style as unmeasured. For prospective results require the new schema and exact configuration even when reviewing the sealed control. Scope the authorization to read a historical configuration narrowly. Default admission still requires a full, positive receipt for the active exact candidate.

**Automated acceptance.** Use the real serializers, CLI, files, blind join and scorer with a synthetic sender at the transport boundary. Cover the exact comparison and alternative branches end to end. Test missing approval, exhausted envelopes, reserved-but-interrupted runs, concurrent starts, duplicate occurrence, wrong model, held-out tuning ID, learner ID, stale configuration, missing style, equal Middle count, invented causal link, absent required exception, incomplete stream and a script invoked with optimized Python. Inject a crash after reservation and before and after send. Reopen, show the reserved state and verify no replay. Swap two answers for the same case across arms, omit a case and substitute a control receipt for a treatment. Each must fail. Read historical rejected/tuning evidence without changing its bytes or granting admission. Run independent review, repair, simplify and the full sequential local gate.

**Human acceptance.** Rehearse the rubric with the archived calibration items. Readers must articulate why “so” can add a cause, why omission of the metaphor is a style miss, and why shortening cannot excuse a lost condition. Inspect the prospective sanitized receipt, aggregate budget preview and recovery messages. The step passes when another operator can reproduce a six-case rehearsal and distinguish a failed case, an interrupted run and a rejected receipt without access to a provider key.
