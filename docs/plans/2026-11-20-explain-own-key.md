## Provider and learner eligibility

A person who presses Explain directly is an end user. Keep the account holder, operator and intended reading level distinct. Simple wording is available to adults. A learner typing “I am 13” in About me neither establishes consent nor authorizes transmission.

- **OpenAI.** The API agreement covers businesses and developers, requires guardian consent for minor use, and restricts key transfer. The key-safety guide recommends a backend for a developer's secret. Separate account guidance discusses the risk of a user entrusting their own key to a third-party tool. Applicability to this direct, user-held native key is an inference. Verify the intended account category before offering it. Disclose ordinary abuse-monitoring retention and opt-in training rules. Responses `store: false` alone does not establish Zero Data Retention (ZDR). [Services Agreement §§1–3](https://openai.com/policies/services-agreement/) · [Key safety](https://help.openai.com/en/articles/5112595-best-practices-for-api-key-safety) · [Third-party tools](https://help.openai.com/en/articles/8304786-keeping-your-openai-account-secure) · [Data controls](https://developers.openai.com/api/docs/guides/your-data)
- **Anthropic.** Eligible commercial API customers may power end-user products. The terms exclude consumer use and require telling listeners to independently check factual claims. They do not establish that any household can open a qualifying API account. Standard API deletion is within 30 days, subject to model, legal, policy and contract exceptions. Flagged inputs/outputs may be retained up to two years. Check the selected model and exact service before writing connection copy. [Commercial Terms §§A, B and D](https://www.anthropic.com/legal/commercial-terms) · [API retention](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data) · [Model-specific requirements](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention)
- **Direct learner use.** OpenAI's under-18 guidance calls for age-appropriate safeguards and ZDR before processing personal data of children below 13 or the applicable age of digital consent. In Spain, 13 is below the age at which a child can independently consent to this processing. Arbitrary captured text and a listener profile may contain personal data. A routine OpenAI key with parental consent does not establish the necessary controls for that case. Anthropic's guidance covers technical safeguards, regulatory disclosures and clear AI identification when minors interact directly. A parent entering the key alone does not establish a qualifying Anthropic customer or those safeguards. [OpenAI under-18 guidance](https://developers.openai.com/api/docs/guides/safety-checks/under-18-api-guidance) · [Spanish Data Protection Act, Article 7](https://www.boe.es/eli/es/lo/2018/12/05/3/) · [Anthropic guidance for minors](https://support.claude.com/en/articles/9307344-responsible-use-of-anthropic-s-models-guidelines-for-organizations-serving-minors)

**Admission rule.** Default direct-learner routes to unavailable. For a qualifying route Phase 1 must record primary evidence for jurisdiction, age band, customer category, applicable guardian authorization, provider/project settings and a practical verification method. Setup must bind the verified configuration to this key and learner use, minimize local data and protect adult-only changes. Use local setup with the guardian/eligible administrator. Store only the minimal status and binding needed, with withdrawal and recheck on change. A text-field assertion, a date inferred from the device, or a successful API request cannot establish these facts. Test age-appropriate onboarding, user-visible help/reporting, locally enforced input and pre-speech output safeguards, blocked content and recovery. Do not add cloud age verification, another moderation destination or a shared developer credential. If a route requires evidence or public disclosures unavailable in this design, keep it disabled, explain why, and retain the direct-use case in the qualification matrix. No direct learner route is currently verified. This is a product admission rule, not certification of legal compliance. Sources checked 2026-11-20.

## Stuck states and recovery

| State | What the person hears or sees and how it ends | Recovery-or-disclosure oracle |
| --- | --- | --- |
| No key, learner eligibility unknown, withdrawn consent, unsupported account/model | Explain pane names the missing condition. Connect or revisit eligible setup. Local Read is available immediately. No capture or send. | P2/P4 drive each state through both shortcuts, then valid setup or local Read. Assert zero provider calls while blocked. |
| Keychain locked, denied, stale or deletion interrupted | Pane names Unlock/Retry, Replace key or Finish disconnect. A pending deletion stays visible across relaunch and prevents dispatch. | P2 deny and restore access, interrupt at every durable write, relaunch, verify deletion and reconnect once. |
| Shortcut missing/collides, or system shortcut is taken | Recorder identifies the internal collision. For external conflicts show re-record guidance. Read setup stays independent. | P4 reload old preferences, check ordered pairs and re-record a working binding. |
| Voice preparing, damaged or output device unavailable | Show preparation or Voice repair instructions. If local speech cannot run, route to visible recovery. A later press works after repair. | P3/P5 withhold voice, change device or fail scheduling, then restore and complete a fresh dispatch. |
| Accessibility or Screen Recording absent, overlay unavailable, macOS needs relaunch | Open the correct Setup control with Grant or Quit and reopen. If presentation is unavailable use local spoken guidance when possible. | P3/P4 revoke/simulate denial, grant/relaunch, capture once, verify source focus. |
| Empty selection/region, stale copy, unsupported source, unreadable OCR, over limit | After the chime give one local sentence with the applicable action: select text, use Explain region, redraw, or shorten. Refuse to send unrelated text. | P3 empty/failed then valid press, 3,000/3,001 boundary, clipboard sentinel and zero requests on failure. |
| OCR slot busy, capture/recognition timeout or hanging worker | Disclose that the region could not be read and offer retry or selection. Esc cancels silently. Keep the OCR slot until the actual worker ends. | P3 retain a timed-out worker, reject competing work, release worker, complete a new region. Selection can still proceed. |
| Invalid/expired key, insufficient credit, billing or rate limit | One local sentence names Replace key, provider billing, or Try again later. Visible help matches the cause. | P2/P4 cover each status and fresh deliberate success. No automatic retry or provider change. |
| Offline, timeout, refusal, retired model, malformed response, output bound, redirect or policy block | Speak one short explanation with the available action. Direct back to Read for refused/unsupported content. Expose persistent setup problems in the panel. | P2/P3 inject each before first speech, verify exactly one message and fresh success or visible unavailability. |
| Stream fails after speech starts | Stop remaining generated audio and tell the listener it was interrupted. The next deliberate press starts afresh. | P3 fail after sentence one, assert no later partial speech, one local message and idle glyph. |
| New press, disconnect, revoke, quit or voice reinstall during work | Cancel obsolete capture/network/speech and remove activity. Keep deliberate stop/Esc quiet. | P3 force late data, completion and chime callbacks at each await. Assert no obsolete audio, send or status. |
| Prompt/model changes, qualification fails or native latency misses | Candidate remains unavailable for the affected route.
