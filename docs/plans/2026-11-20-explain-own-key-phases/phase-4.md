# Phase 4 — Connect from the menu bar and invoke either shortcut

Requires [Phase 3](phase-3.md). Add an Explain tab in the existing monochrome popover. Keep the rail, typography, focus behavior and existing template glyph. Use the glyph's activity state with an accessible description while generation is in progress.

## Work

- Add two unbound shortcut names with fixed meanings, Explain selection and Explain region. Preserve existing stored Read names and behavior through upgrade. Compare each binding against every other action, handle clearing and re-recording, and name the conflicting action. Setup readiness for the local reader continues to depend only on its existing required items. Explain is optional.
- Disconnected view offers the eligible provider list, official create-key and billing help, a secure field, and an explicit local Save/Connect. Name what leaves the Mac (deliberately captured text, settings including About me, and the instruction), where it goes and who pays. Explain region sends text inside the chosen rectangle. Disclose AI generation, model-specific retention/training and the need to check important facts. Avoid a promise of zero retention. The connection uses an eligible API account. A consumer chat subscription alone does not supply the API credential.
- Connected view identifies the selected provider, connection status and Disconnect. Provide Replace key/Change provider with a fresh disclosure and eligibility check. Show the three-stop slider (Middle by default), Plain by default, Real-life examples, Metaphors, Paint a picture, one optional single-line About me field, and both recorders. Use explicit local preferences with stable keys. Cap the profile at 240 characters and display the limit. Explain that saved background goes to the connected provider on each Explain. Persist only the intentional profile/settings and nonsecret connection state. Display the saved profile only in its editable listener-settings field. Let the user edit or clear it and test both across relaunch. Keep the existing key out of every field, and exclude both key and profile from overview text, diagnostics and actual screen captures for the test report. Use synthetic fixture identities only.
- Apply the audience policy before enabling cloud use. Keep an eligible adult account holder in control of credentials/configuration on learner setups. Give a directly operating learner an age-appropriate disclosure, visible help/reporting and unrestricted access to the local reader. If jurisdiction, account controls, guardian authorization or safeguards cannot be established, show the reason and a Read action before collecting/sending a passage. Changing the free-text profile cannot establish eligibility. Make consent withdrawal and key replacement invalidate the learner route immediately.
- Route recovery to the specific control in the already-open or newly opened panel. Handle hidden/occluded menu item without stealing focus. If an audible recovery is possible, name the menu-bar control or System Settings step. With audio unavailable, retain a visible status until resolved. Stop generation activity on every terminal outcome. Ordinary Read actions carry no Explain chime, cloud status or setup prompt.
- Update the current product position in the briefing, README and controlling instructions as needed, preserving historical decisions and upstream attribution. Document eligibility, supported providers, local key deletion and separately revoking a key at the provider. For an Anthropic learner route prepare the required public-facing disclosures locally. Actual publication is a separate action.

## Acceptance

**Automated.** Drive all 12 ordered shortcut collisions and valid rebind/clear/relaunch scenarios, exercising registered actions to the recording transport and local sink. Load existing two-shortcut preferences. Read-only installs open as before and make zero network attempts. Exercise Save, first use, invalid key, replace, disconnect and refused Keychain deletion. Check mandatory/optional input, focus, keyboard navigation and VoiceOver labels. Exercise disconnected, connected, learner blocked/eligible, key error and partial-interruption fixtures in both appearances. Validate script fixture inventories and render dimensions. Suppress secret/profile output in fixture/debug commands. Cover already-open panel and completion from an obsolete request.

**Manual.** Inspect local renders at the existing popover size, scroll to each action, use the recorders with a keyboard and operate setup using VoiceOver. Rehearse the complete setup flow with a synthetic disposable key and fixture transport. The live first-time-user acceptance belongs to Phase 5 on the signed candidate. Keep observed steps and outcome only.

**Work units.** Core shortcut validation plus its tests and the panel fixtures/views are [batch-eligible] with separate owners and a fixed four-action interface. The integration owner wires app state, status item, debug/verification scripts and docs, then drives both real shortcuts. No tab or disabled control should advertise an unqualified provider.
