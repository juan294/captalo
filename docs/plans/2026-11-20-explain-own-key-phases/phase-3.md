# Phase 3 — From deliberate capture to streamed local speech

Requires [Phase 2](phase-2.md). Exercise the application action methods through injected boundary adapters before registering the two public shortcuts. Keep one owner of input order and active speech.

## Work

1. Carry a purpose (Read or Explain) beside the existing selection/region kind. Reserve a generation synchronously at key-down, before focus lookup or any Keychain await. Snapshot eligible connection identity, depth, style, profile, voice and speed for this press. Acquire source focus before opening any panel. For Explain, start the bundled approximately one-second meditation chime immediately on its own audio channel, show activity, and check eligibility, voice and permissions before capture or send. Region starts the existing user-drawn overlay. Only the selected region's local OCR text, in block/row order, may enter the request. Ensure table boundaries remain intelligible. Never send pixels, surrounding material, undisclosed clipboard contents or a shortened input.
2. Reuse the clipboard transaction, capture validation, one OCR slot and cancellation cleanup. Dispatch once after a final current-ticket/credential check. Define one word as a nonempty whitespace-delimited token, matching the frozen source generator. Accept 3,000 inclusive. At 3,001 speak “Explain supports up to 3,000 words. Choose a shorter passage.” Reject a source over 256 KiB of UTF-8 before transmission, even if it contains few whitespace delimiters. Give a distinct “This passage is too large. Choose a shorter passage.” message. Test both edges of the byte bound. Treat whitespace-only input and cleanup-only content as empty. No request for cancelled, failed or empty capture.
3. Preserve Read's existing same-selection and empty-selection stop gestures, region replacement-on-success and failed/pending capture behavior. Same source with different purposes must be able to start the new action. For Explain selection use the same-source repeat to stop its active Explain without sending again. A new ordinary Explain press supersedes older pending Explain input/generation. Validated Explain takes the playback slot at promotion. Failed pending capture keeps an existing Read session intact. For feedback while Read is active, suspend/duck its local output for the short message, then restore it. Explicit Esc/replacement/quit cancels silently. Document that cancellation cannot recall text already sent. Stop, replacement, disconnect, voice repair, unrecoverable device failure and quit must each release the network task, queued generated audio, capture resources and stale activity. In the existing voice preview route, keep pending Read input behavior and invalidate pending or streaming Explain before it can spend or speak again.
4. Add an incremental unit source to the existing bounded ReadingSession. Keep the finite iterator entry point for Read. A temporarily empty stream waits for more data. Complete sentences flow to Kokoro at once, with increasing unit IDs across sentences. Await the press's full chime completion before its first speech reaches the sink. Use actual playback completion; synthesis can overlap the chime. Each accepted key-down plays its full chime. Rapid distinct presses can overlap acknowledgements on the chime channel, while only the current request may speak after the outstanding chimes finish. Ignore OS key-repeat for one physical press. Reset activity only for its owning generation.
5. Segment across delta boundaries, handling abbreviations, decimals, punctuation/closing quotes, line breaks and Unicode. Flush a final speakable fragment only on a natural provider end. Keep both generated text and PCM bounded in memory, applying backpressure or a disclosed failure if a bound is exceeded. Preserve the existing audio lookahead, route-change replay and a single Kokoro inference in flight. For a learner route apply its qualified input and output safety controls before send and before any sentence can be heard, including context spanning sentences. Hold or withhold the learner route if the controls cannot safely work incrementally within the latency limit.
6. On provider failure, stop pending output. If the listener has heard any of this answer, say once “The explanation was interrupted. Try Explain again.” Otherwise speak the mapped short reason and recovery action. Use the local voice, with visible recovery if that voice cannot play. No stale network/speech/error callbacks after supersession.

```
@ explainPress(kind) -> spokenOutcome
ctx: ordered input owner, local capture, connection, Kokoro and audio device
do:
  1. emit chime and reserve press before awaiting source
  2. validate eligibility, capture outcome, input size and current generation
  3. emit qualified request and parse speakable sentences in order
  4. emit current authorized audio after chime completion
br: explicit stop -> cancel pending work and silence its speech
fail: partial stream -> drop queued answer and disclose interruption once
```

## Acceptance

**Automated.** Drive both action methods with synthetic capture, irregular SSE chunks, controllable deadlines, a deterministic audio sink and a late-finishing worker. Assert exact ordered sentences once, full-chime barrier, no raw-source Read on Explain, no provider call on Read, no obsolete send, stale speech, stale error or stuck activity. Cover press-before-focus ordering, Read/Explain on identical text, same-selection stop, Esc during drag, empty selection, refused clipboard ownership, OCR busy/timeout and recovery, delayed first sentence, stall after speech, 2,999/3,000/3,001 words, middle exception in the long fixture, partial terminal frame, final fragment, slow audio and device restart. Test stop/quit/disconnect during capture, send, sentence wait and playback. Prove a fresh request works after each recovery. Preserve the finite reader's complete playback, buffer bounds and stale callback suites. The silent probe cannot prove audible output.

**Manual.** Integration owner verifies actual onset, chime character, clipboard restoration, focus and hardware in Phase 5. Log the distinction between a device callback, scheduled samples and the first audible word.

**Work units.** The incremental speech source/sink tests and the capture-side purpose dispatch are [batch-eligible] after agreeing the event contract, in separate Reading and Request file sets. Integration owner owns app-state composition, one chime asset/channel, global ordering and tests crossing both units. Sequence the combined change before exposing shortcuts.
