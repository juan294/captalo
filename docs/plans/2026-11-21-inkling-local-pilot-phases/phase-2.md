# Phase 2. Run the six passages once on the Studio

**Entry.** Accept Phase 1. Execution scope includes acquiring the pinned original checkpoint and runtime and running the six synthetic passages. Only the integration owner operates the Studio. The download and dependency installation are explicit setup steps. Check current free space for the transfer, final snapshot and runtime before allocation. Record paths, owner, evidence location and intended retention. Keep downloaded weights as a reusable owner asset pending the verdict. Use a private, ignored evidence directory under the primary checkout so an implementation worktree can be removed without losing results.

1. **Acquire and validate.** Install the reviewed runtime pin in its own environment, resolve and freeze dependency versions and hashes, and verify the snapshot against immutable repository metadata. Validate the main tensor size and hash as well as each loaded local file. Supply the local snapshot path. Exclude the optional draft model. Run a neutral, unscored prompt with no corpus overlap to check load, effort, final-channel extraction and EOS. Exit the smoke-test process before measurement. Record any unexpected runtime conversion or asset fetch as a setup failure.
2. **Verify isolation and voice condition.** Use an outbound-deny sandbox for the model process and children, local-only library settings and an allowlisted environment without provider credentials. A disposable control process under the same profile attempts a connection and must be denied detectably. A local-only control must finish. Keep the machine’s network settings intact. Prepare the bundled voice and keep it resident throughout generation using a task-owned helper and disposable voice store. Require a real readiness result and a synthetic warm-up that produces PCM. Record voice, store, PID and baseline memory. The previous sentence-timing probe demonstrates this measurement setup. [Offline control](../../../Scripts/offline-test#L130) · [Voice setup](../../../Packages/CaptaloSpeech/Sources/CaptaloSpeech/VoiceSetup.swift#L41)
3. **Measure six consecutive rows.** Reserve the run identity exclusively. Record one start per case before generation, one terminal event afterwards, in the order from Phase 1. Use one fresh model process for the first row and keep weights resident for the next five. Give every row a fresh conversation and KV cache. Cold means fresh process and unloaded weights. The file cache may be warm from setup. Record that distinction. Use an explicit 300-second per-row watchdog as an operational limit and record its outcome separately from a natural model stop. Use monotonic clocks for load start, model-ready, request submission, first final token, first complete final sentence and terminal event. For the cold row report both load-inclusive and submission-only durations. For all rows report request-to-first-sentence and total duration. Timestamp events when observed, including the time spent reasoning and prefilling. Use a frozen sentence-boundary rule with tests for decimals, abbreviations and terminal punctuation. A sentence recognized only at natural end takes that end timestamp.
4. **Account for memory and finish.** Record the MLX allocator peak and process peak resident memory with units and sampling method, plus the resident voice helper’s footprint and host memory pressure/swap before and during the run. Distinguish process lifetime peaks from per-row observations and avoid adding overlapping memory measures. Record terminal reason, token counts, full prompt hash, final answer hash and final synthetic answer for blind review. No prompt, thinking trace or answer belongs in ordinary application logs. Stop only the verified owned children. Record retained model assets and private evidence with their next review at the Phase 3 verdict.

```text
@ observeCase(row, stream, clock) -> privateObservation
pre: run owns this unattempted row and the voice is ready
do:
  1. write the attempt before submitting the prompt
  2. parse generated token IDs into model channels
  3. emit marks only for final text and its first complete sentence
  4. write final answer, measurements and actual stop reason
fail: timeout, cap, malformed channel or process exit -> preserve observed marks and cause
```

**Automated acceptance.** Verify the control outcomes, setup digests, six distinct attempt IDs, 3,000-word source integrity, one terminal disposition per attempted case, ordered clock marks and traceable memory measures. Missing answers and absent timestamps are explicit. Never infer a first sentence from a tokens-per-second figure. Keep watchdog, MLX error, OS kill and EOS distinct. Recheck file hashes and run the full sequential verification for the phase.

**Manual acceptance.** The owner reviews the process and voice evidence, whether each timing is cold or warm, interruptions and teardown. Show a six-row table with individual times and failures. Keep five short cases and one long case distinguishable. Stop here for phase acceptance before opening the blinded packet. This phase has one hardware owner.
