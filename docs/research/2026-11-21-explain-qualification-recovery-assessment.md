## Offline feasibility and reviewer calibration

Two independent reviewers read the same nine anonymous items under the frozen rubric. Six were archived pilot answers and three were reference answers written for this assessment. They agreed on seven of nine factual labels and all nine judgments of whether the requested style was recognizable. This selected sample tests specific disagreements; it does not estimate overall reviewer accuracy. The original receipts retain their original verdicts.

- Both reviewers rejected the cup answer that linked an unmeasured temperature to an unresolved cause with “so.” They accepted a 33-word reference that states the starting conditions, observation and limits in separate sentences.

Both accepted the later answer, which explicitly says that the passage leaves those locations unknown. My prior handoff overstated reviewer variability as the explanation for this pair. ## Smallest experiment that could change the decision

1. **Construct the active task in Swift.** The current OpenAI system message describes all three depths and all four styles on every request. Use the selected depth/style enums to compose one trusted instruction. For a 40-word Middle input, tell the model the maximum is 39 words including the comparison. Keep the soft target distinct from the maximum. Give a signalled likeness only to a style that calls for one. Captured text and the listener profile remain separate untrusted data fields. Freeze the instruction components and the exact request bytes. This changes the existing builder at `Packages/CaptaloCore/Sources/CaptaloCore/Explain/ExplainCandidate.swift:17` and `:53`. The number guides generation; the existing local count determines whether the answer passed.
2. **Measure one change at a time.** Compare the current instruction and the selected-task version on matched original-corpus cases. If needed, add one approved short, worked example for the selected style as the next experimental arm. Use a new synthetic topic for the example and keep held-out cases sealed. Include an unchanged control repeat on the difficult cases so ordinary run-to-run variation stays visible. Track unsupported claims, required omissions, word count and recognizable style separately. Preserve a failed answer even if a repeat passes. OpenAI's evaluation guidance also recommends calibrating automated judgments against human examples. [OpenAI evaluation best practices, checked 2026-11-21](https://developers.openai.com/api/docs/guides/evaluation-best-practices)
3. **Advance only on evidence.** A faithful answer that silently drops the requested metaphor is a diagnostic miss. Use blinded reviewers with reference examples and adjudicate disputed scope against the passage. Juan's listening judgment remains the test of whether the distinctions are useful by ear. A clean diagnostic candidate still needs its own 83-case qualification run before integration. If factual errors persist after the controlled comparison, test a different model under the same protocol or return the provider decision to Juan. No change to the admission threshold follows from this assessment.

A whole-answer validator could count exactly before playback. It cannot establish that a causal link is supported, and waiting for the complete answer changes the planned speech timing. Five of 64 historical Terra requests with inputs up to 300 words already took over three seconds to return their whole answer, before local synthesis and playback. Exact source quotations could anchor claims, but an accurate quote can still omit a condition or support a misleading comparison.
