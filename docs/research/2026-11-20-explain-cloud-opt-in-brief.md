# Design Brief: Explain it my way, as an opt-in cloud feature

> Brainstormed on 2026-11-20 with the owner, in the same session as the first brief. This brief supersedes [the local-only brief](2026-11-20-explain-my-way-brief.md) for the engine, the privacy constraint and the success criteria. The first brief is kept unchanged because [the engine assessment](2026-11-20-explain-my-way-engine-assessment.md) cites it by digest and line number. No project overlay exists at `.rpi/project/rpi-brainstorm.md`, so the stock `rpi-brainstorm` procedure applied without overrides.

## Owner decision of 2026-11-20

The owner changed the product constraint: **Read is always local. Explain is an opt-in feature that sends the captured text to a cloud language model.** This replaces "local only" for the Explain action and for nothing else. The owner made the decision after the engine assessment found that neither local candidate keeps the facts of the source.

## Problem

Cáptalo reads visible text aloud, from a selection or from a screen region. A full read is often more than the listener needs, or not the form the listener understands best. Someone who reads emails, documents and LLM output all day wants the content explained at a chosen depth and in a manner that suits them: in plain words for a non-technical person, with real-life examples, as a metaphor, or for a 13-year-old learner.

The engine assessment tested two local engines on 70 cases each. Apple's on-device model passed the faithfulness check on 33 and Qwen3-4B on 16. About half of the plain summaries also failed, so removing the styles does not rescue a local version. The listener hears the result and cannot see it, so a changed fact goes unnoticed. The full feature needs a stronger model than an ordinary Mac can run today.

## Goal

A second action, on its own shortcuts, that speaks an explanation shaped by the listener's settings, generated by a cloud model that the user has chosen to connect, while the reader stays local and unchanged.

## Scope

**In (this effort):**

- Two new user-chosen shortcuts with fixed meanings: "Explain selection" and "Explain region".
- Listener settings in the menu-bar panel: a depth slider (simplest wording to detailed, default in the middle), a style list (Plain, Real-life examples, Metaphors, Paint a picture), and one free-text "About me" line.
- Explain is off until the user connects a provider. The panel states that the captured text is sent to that provider for explain requests only.
- **Own-key access.** The user enters an API key for a supported provider. The app links to documentation that shows how to create one. The key is stored on the user's Mac only and is sent to that provider only. No Cáptalo server or database receives or stores it.
- **Three providers under test:** OpenAI, Anthropic and Google Gemini. The owner wants to test all three before deciding and is in no hurry.
- Wait handling as decided before: a signature chime of about 1 second in a meditation character plays at once on the key press and in full, the menu-bar glyph shows activity, and speech starts when the chime has ended and the first sentence is ready.
- The spoken output uses the existing local Kokoro voice. Only the explanation text comes from the cloud.

**Direction recorded, not part of this effort:**

- **A paid plan with no setup.** The user pays monthly, by card through a payment provider such as Stripe, and Explain works at once with the owner's provider accounts and a mid-tier model. The user can cancel at any time and change to an own key. The owner stated that the payment part does not need to be implemented now. It needs its own brief, because it adds components this project does not have (see Open Risks).
- The earlier backlog: "what is asked of me", explain a single word, outline, listenable read, skeptic, translate, ask by voice, and an option to turn the chime off.

**Out:**

- Any network use by the read shortcuts, the OCR or the speech.
- Any network use by Explain before the user connects a provider.
- A local engine for Explain at this time. The frozen 70-case corpus stays as the gate for a retest when local models improve.
- Sign-in with a consumer subscription (ChatGPT, Claude or Gemini apps) as the connection method, unless the assessment finds a route that the provider's terms allow for a distributed third-party app.
- Rephrasing for tone, languages other than English, saved profiles, a transcript view, a chime on the read shortcuts, and a mode switch on the read shortcuts.

## Constraints

- Read, OCR and speech stay on the Mac with no network connection. This is unchanged.
- An explain request sends the captured text, the listener settings and the instruction to the one provider the user connected, and to no other destination. The app does not retain the captured text or the generated text on disk or in logs. `PrivacyLog` remains the only logging API for app code.
- The user's API key never leaves the Mac except as the credential in requests to its own provider. The owner requires that the project holds no user keys and carries no responsibility for them.
- One code path per action and no fallbacks without approval. An explain request uses the connected provider. A failed request does not move to another provider or to a local model.
- The app stays nearly invisible: no Dock icon, no floating window, settings in the menu-bar panel.
- macOS 26 minimum, Swift, SwiftUI and AppKit, with pure logic in `Packages/CaptaloCore`.
- Provider spending for tests, and any credential setup, need the owner's explicit authorization.
- `AGENTS.md` and `docs/briefing.md` state the old all-local rule and must be reworded to match the decision above.

## Chosen Approach

**Cloud model, opt-in, with the reader untouched.** The local-only approach was tried first and measured. It failed on faithfulness, which the first brief set as pass or fail. The alternatives were to park the feature, to build a key-sentence summary that only quotes the source, to use a larger model that only high-memory Macs can run, or to lower the faithfulness bar. The owner chose the cloud option because it is the only one that keeps "About me", the styles and simplification. The key-sentence summary would have lost all three. The privacy position is kept by the default: a user who connects nothing has a fully local app.

**Two access routes over time.** Own key first, for users who accept some setup and do not want to pay the owner. A paid plan later, for users who want the feature without setup. The owner judged this a good balance: the original feature is free and local, and the advanced feature has a free hands-on route and a paid simple route.

**Three providers tested before any is fixed.** Rejected: starting with one provider chosen on paper. The owner wants evidence from OpenAI, Anthropic and Gemini. The same frozen corpus and scoring that judged the local engines will judge them, so the results are comparable. How many providers the product supports is decided after that test. If more than one is supported, the user selects one, and each request still has one path.

**Model tier.** For the paid plan the owner indicated a mid-tier model from each provider. The assessment tests the current mid-tier and fast-tier model of each provider, because cost per request and time to first sentence both depend on the tier.

**Unchanged from the first brief:** hybrid settings model, two new shortcuts with fixed meanings, short fixed chime with glyph activity and first-sentence start. The reasons and rejected alternatives are in the first brief.

## Success Criteria

1. **Faithfulness.** On the frozen 70-case corpus, the explanation states no fact, number, name or instruction that the source does not contain, and "About me" never overrides a fact in the source. The first brief set zero failures as the bar. Whether a cloud model reaches zero is unknown, and any tolerance is an owner decision made with the results in hand.
2. **The settings change the result audibly.** For the same text, the owner can tell the leftmost, middle and rightmost slider positions apart by ear, and can tell each style apart.
3. **"About me" is respected.** With "I am not technical" in the field, an agent report is explained without unexplained jargon. With a profession in the field, a comparison comes from that field at least once.
4. **Time to first spoken word.** At most 3 seconds from the key press for a text of up to 300 words, on the owner's Mac and network. The chime starts at once on the key press.
5. **Long text.** A selection of 3,000 words produces a complete explanation with no silent truncation. Above the supported limit, the app says so in one spoken sentence.
6. **Read stays local and unchanged.** The two read shortcuts work with the network disabled, attempt no connection, and play no chime.
7. **Explain sends only what it must.** With no provider connected, Explain attempts no connection. With one connected, traffic goes to that provider only, and only on an explain request. The captured and generated text are not written to disk or logs.
8. **Key safety.** The key is stored in the macOS Keychain, is absent from logs, preferences files and the install record, and is removed when the user disconnects the provider.
9. **Setup by a non-developer.** A person who has never created an API key can connect one provider by following the linked documentation.
10. **Failures are clear.** With no network, an invalid key or a provider refusal, the listener gets one short spoken sentence that states the problem, not silence and not a partial explanation presented as complete.
11. **The chime.** It plays in full on every explain, lasts about 1 second, and the owner judges it pleasant after a week of repeated use.
12. **Owner verdict.** After one week of the owner's own use on real emails, documents and agent output, the owner still uses the feature and judges it helpful for understanding.

## Open Risks

- **Cloud quality is expected, not measured.** Frontier models should keep facts far better than the two local engines. No cloud model has run the corpus yet. If none passes, the decision returns to the owner.
- **Errors remain hard to notice by ear.** A stronger model lowers the error rate and does not remove the risk. Criterion 1 needs a defined bar.
- **Subscriptions and API access are separate accounts.** Checked on 2026-11-20 in the owner's accounts: each provider has an API organization that is distinct from the consumer subscription and holds its own credit. OpenAI's billing page shows a ChatGPT subscription linked to the API organization, with subscription credits applied to it, so the two are not fully separate there. Still from memory and not verified: whether a user of a distributed third-party app may connect with a subscription login in place of an API key under each provider's terms. The assessment must verify that, and the later paid-plan study must verify whether the owner may resell access through an API account.
- **The owner's setup can run the test.** Checked on 2026-11-20: an OpenAI API key is present in the shell environment and lists current models; the Anthropic Console organization has credit and automatic reload but no key in the environment; Google Cloud has billing-enabled projects with the Gemini API enabled but no key in the environment and none created for Cáptalo.
- **The paid plan needs a server.** The owner's keys cannot be placed inside the app, where any user could extract them. A paid plan therefore needs a service that holds the keys, checks who has paid, limits use and forwards requests. The project today has no backend, database or cloud runtime, and `AGENTS.md` says none is required. With that service, users' captured text passes through infrastructure the owner operates, which brings a privacy policy, data handling duties, abuse control and running costs that scale with use. Pricing must cover the per-request cost.
- **Region capture can send unintended text.** A rectangle can include content the user did not mean to share with a provider.
- **Provider data handling differs.** Retention and training rules vary by provider and by account type. The connection screen must state them accurately.
- **Instructions inside captured text.** A document can contain text that acts as an instruction to the model. The plan needs a position on this and on the free-text "About me" channel.
- **Three integrations to maintain.** Each provider has its own interface, errors, model names and deprecation schedule.
- **Network dependence.** The wait now varies with the connection. The chime covers about one second.
- **Empty capture.** The chime plays on the key press, before the app knows whether a capture succeeded. The behaviour is undefined.
- **Product position.** "The local option for privacy" now depends on the default and on clear wording at the point of connection. The copy and the briefing describe a local reader.
- **Chime fatigue** and **revenue from removing the chime** remain as recorded in the first brief.
